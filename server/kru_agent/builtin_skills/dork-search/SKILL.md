# Пошук операторами (дорки)

Оператори звужують пошук до потрібного типу файлів, сайту чи формулювання — замість сотні загальних
посилань кілька точних. Пошук іде через web_search (DuckDuckGo або SearXNG): запит передається як є.

## Оператори

| Оператор | Що робить | Приклад |
|---|---|---|
| `"…"` | точна фраза | `"Cybersecurity Framework 2.0" "Quick Start Guide"` |
| `site:` | лише цей сайт / домен / зона | `site:nist.gov`, `site:gov.ua`, `site:edu` |
| `-site:` / `-слово` | виключити сайт чи слово | `-site:pinterest.com -курси` |
| `filetype:` | тип файлу | `filetype:pdf`, `filetype:pptx`, `filetype:xlsx` |
| `intitle:` | слово в заголовку сторінки | `intitle:"cheat sheet"` |
| `inurl:` | слово в адресі | `inurl:docs`, `inurl:publications` |
| `OR` | будь-який із варіантів (ВЕЛИКИМИ) | `filetype:pdf OR filetype:pptx` |
| `before:` / `after:` | дата (лише Google через SearXNG) | `after:2024-01-01` |

DuckDuckGo розуміє `"…"`, `site:`, `-`, `filetype:`, `intitle:`, `inurl:`; складні комбінації й `before:`/
`after:` — ненадійно. Порожній результат — спрости запит (прибери оператор за оператором), а не вигадуй.
Свіжість без `after:` — додай рік у запит («2026») або шукай kind="news".

## Як шукати

1. Зрозумій, що саме потрібно: тип (документ, офіційне джерело, дані, приклад), мова, свіжість.
2. Склади 2–4 запити від вузького до ширшого, напр. для «офіційні матеріали NIST CSF 2.0 у PDF»:
   - `site:nist.gov "CSF 2.0" filetype:pdf`
   - `site:nvlpubs.nist.gov "Cybersecurity Framework" 2.0`
   - `"NIST CSF 2.0" "quick start guide" filetype:pdf`
3. Відкривай найкращі результати (fetch_url / download_url для файлів), перевіряй, що це справді те:
   автор, дата, офіційність. Посилання з пошуку не вважай фактом, поки не відкрив.
4. Відповідь: що знайдено (назва, джерело, дата, посилання), які запити спрацювали — щоб користувач міг
   повторити. Корисний запит можна зберегти в навичку (save_skill), якщо пошук повторюватиметься.

## Типові задачі

- **Документи й презентації на тему:** `"тема" filetype:pdf site:edu`, `"тема" filetype:pptx`.
- **Офіційні джерела:** `site:gov.ua`, `site:europa.eu`, `site:nist.gov`, `site:iso.org` + точна фраза.
- **Обговорення реального досвіду:** `"помилка" site:stackoverflow.com`, `site:reddit.com "тема"`,
  `site:github.com "назва бібліотеки" issue`.
- **Вакансії / компанії:** `site:djinni.co "Python" "remote"`, `site:jobs.dou.ua "AI"` (див. job-search).
- **Аудит СВОГО сайту** (лише доменів користувача — спитай, які саме його): що з них проіндексовано зайве:
  `site:мій-домен.ua filetype:pdf OR filetype:xlsx OR filetype:docx`, `site:мій-домен.ua inurl:admin`,
  `site:мій-домен.ua intitle:"index of"`, `site:мій-домен.ua "конфіденційно"`. Знайдене — перелічи з
  порадою (прибрати файл, закрити теку, robots.txt / noindex, пароль), і це практика до NIST (ID.AM, PR.DS).

## Межі (обов'язково)

- Не шукай і не збирай персональні дані приватних осіб (адреси, телефони, документи, акаунти конкретної
  людини) і не складай на людей «досьє» — відмов і поясни коротко. Публічні особи — лише їхня публічна роль.
- Не шукай на ЧУЖИХ сайтах відкриті паролі, ключі, бази, конфіги, вразливі адмінки чи камери; дорки «на
  вразливості» — лише для доменів, які належать користувачу (або є письмовий дозвіл на тестування).
- Якщо випадково натрапив на чужі чутливі дані — не відкривай і не завантажуй їх, не цитуй; скажи
  користувачу, що такі є, і порадь повідомити власника.
- Не обходь платні доступи, логіни й заборони сайтів.
